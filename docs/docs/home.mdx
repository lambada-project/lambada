```ts title="index.ts"
import * as pulumi from '@pulumi/pulumi'
import { run } from '@lambada/core'

const result = run('shop', pulumi.getStack(), {
    tables: {
        orders: { name: 'orders', primaryKey: 'id', envKeyName: 'ORDERS_TABLE' },
    },
    messages: {
        orderPlaced: { name: 'order-placed', envKeyName: 'ORDER_PLACED_TOPIC' },
    },
    api: {
        endpointDefinitions: [{
            name: 'placeOrder',
            path: '/orders',
            method: 'POST',
            callbackDefinition: placeOrder,
            resources: {
                table: { orders: ['dynamodb:PutItem'] },
                topic: { orderPlaced: ['sns:Publish'] },
            },
        }],
    },
    messageHandlerDefinitions: [{
        name: 'sendReceipt',
        topic: 'orderPlaced',
        callback: sendReceipt,
        filter: { attributes: { channel: ['web'] } },
        resources: { table: { orders: ['dynamodb:GetItem'] } },
    }],
})

export const apiUrl = result.api?.url
```

From these lines Lambada builds:

- a DynamoDB table and an SNS topic, named per environment (`orders-dev`, `order-placed-prod`);
- an API Gateway route and a Lambda function that may **only** put orders and publish to that topic. It reads both names from `process.env`;
- a subscriber that SNS invokes only for web orders, and that may **only** read orders;
- a least-privilege IAM role for each function, and a resource group for the stack.

Misspell `orderPlaced` in a grant and `pulumi preview` fails, naming the function, the missing topic and the topics the stack does have.

## Why Lambada

- **Grants by name.** A function lists the resources it uses and the actions it needs. lambada writes its IAM policy and its environment, and nothing else reaches it.
- **Mistakes fail early.** Every name is resolved before a function is built, so `pulumi preview` catches it. Filter policies and schedules are typed against what AWS actually accepts.
- **One language.** Infrastructure and handlers are TypeScript in the same program. A handler is a function you import, not a `file.export` string in YAML.
- **Still Pulumi.** `run()` returns the resources it built. Anything lambada doesn't cover is plain Pulumi next to it, in any provider.

## Packages

| Package | What it is |
| --- | --- |
| [`@lambada/core`](https://www.npmjs.com/package/@lambada/core) | `run()` and everything it builds. Used in your Pulumi program. |
| [`@lambada/utils`](https://www.npmjs.com/package/@lambada/utils) | Runtime helpers for handlers: request parsing, errors, repositories, secrets. Has no Pulumi dependency. |
| [`@lambada/create`](https://www.npmjs.com/package/@lambada/create) | `npm init @lambada my-app`: a starter stack with a devcontainer and tests against AWS Emulator. |
